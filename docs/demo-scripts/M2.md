# M2 demo script: real fire data and places at risk

Fire: La Vall d'Uixó, Castellón, 25-29 July 2026. Data: NASA FIRMS hotspots, measured wind (METAR, Valencia airport), OpenStreetMap places. All saved in `data/fixtures/vall-duixo-2026-07/`.

## One-time setup (human, only to download the data again)
1. `FIRMS_MAP_KEY` in `.env` (free key: https://firms.modaps.eosdis.nasa.gov/api/map_key).
2. `pnpm data:fetch` downloads everything again. Or `pnpm data:fetch hotspots`, `wind` or `places` for one file. The demo itself does not need this step or the network.

## Steps
1. `scripts/check.sh`. Expect `check: OK`. The core tests (`packages/core/src/core.test.ts`) use no network.
2. Each fixture file has its source. Run:
   `node -e 'for (const f of ["hotspots","wind","places"]) { const d = require("./data/fixtures/vall-duixo-2026-07/" + f + ".json"); console.log(f, d.source.name, d.source.fetched_at) }'`
   Expect 3 lines: NASA FIRMS, METAR LEVC, OpenStreetMap, each with a fetch date. The FIRMS URL in the file shows `<MAP_KEY>`, not the real key.
3. `pnpm replay 3`. Expect:
   - A header that starts with `REPLAY of La Vall d'Uixó wildfire`, lists the 3 sources, says `2097 fire hotspots; 7 isolated detections outside the fire ignored`, and says arrival times are ESTIMATES.
   - One line for every hour from `2026-07-25 09:00 UTC` to `2026-07-29 15:00 UTC`, with hotspot count, satellite pass time, wind, spread rate and `at risk ≤1h N, ≤3h N, ≤6h N`.
   - `2026-07-25 09:00 UTC` has 0 hotspots and 0 places (before the first detection).
   - `2026-07-25 14:00 UTC`: 248 hotspots (pass 13:33), wind from the west at 41 km/h, spread 4.1 km/h, `at risk ≤1h 31, ≤3h 74, ≤6h 171`.
   - Each place line: type, name, distance in km, "fire to the <direction>", arrival estimate, and `(near)` or `(downwind)`. Schools and nurseries on 25-26 July (a weekend) say `likely empty: weekend` and come after occupied places.
4. Direction check: `pnpm replay 300 | awk '/^2026-07-25 14/{f=1;next} /^2026/{f=0} f' | grep "care home"`. The care homes in Borriana and Vila-real (east of the fire), for example `Residència de Majors  9.9 km, fire to the west, about 2 hours`, must say the fire is to their west or south-west, never east.
5. `REPLAY_TIME=2026-07-26T02:00:00Z pnpm --filter @evac/agent exec vitest run src/bot/incident.test.ts`. Expect it to pass (a different hour also gives a REPLAY incident with non-empty call facts).
6. **NEEDS HUMAN (Telegram):** `pnpm bot`. Send "Which places are in danger?". Expect: it says it is a replay, the data time `25 July at 15:33 Spanish time`, wind from the west at 41 km/h, the counts per band, and a short ranked list with the same names, distances and directions as `pnpm replay` at 14:00 UTC. Arrival times are called estimates.
7. **NEEDS HUMAN (Telegram):** send "Is Residència de Majors in Borriana in danger?". Expect it to answer from the data (9.9 km, fire to the west, about 2 hours). If the place is not in the top list, it must say that and not guess.
8. **NEEDS HUMAN (phone):** send "Call the care homes", press **Approve**. The demo phone rings. The agent names a real care home from the list, with its distance, fire direction and arrival estimate, and says the data time in Spanish time. Save the call ID in `docs/PROGRESS.md`.
