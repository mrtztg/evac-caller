# M4 demo script: submission

M4 has no new product feature. It checks that what we submit is true: the code is clean, the repo is public and complete, the README does not claim a sponsor we did not really use, and no secret is in git.

Galtea was dropped at the M4 gate (see `docs/DECISIONS.md`), so nothing in the repo may mention a Galtea evaluation.

## Steps

1. `scripts/check.sh`. Expect `check: OK` and 36 tests passing (19 in `apps/agent`, 17 in `packages/core`).

2. No sponsor we did not use: `grep -rn -i galtea README.md .env.example docs/demo-scripts docs/TEST-BEFORE-DEMO.md`.
   Expect **no output**. (`docs/PLAN.md` and `docs/DECISIONS.md` may mention it: they record the plan and the decision to drop it.)

3. No secret in the repo or in its history:
   - `git ls-files | grep -E '^\.env$|evac\.db|data/runtime'` — expect no output.
   - `git log --all --oneline -- .env data/runtime evac.db` — expect no output.
   - `grep -rn "sk-\|Bearer " --include "*.ts" apps packages` — expect no output.

4. Everything is pushed: `git status -sb` shows a clean tree and no `ahead` marker, and `git log origin/master..HEAD --oneline` prints nothing.

5. The README matches the code. Check by hand that each command in the "Setup" section exists in `package.json`:
   `pnpm install`, `pnpm replay`, `pnpm bot`, `pnpm web`, `pnpm agent:sync`, `pnpm call:test`, `pnpm call:status`.

6. The repo is public and complete: open https://github.com/mrtztg/evac-caller in a private browser window (not logged in). Expect the README to render, and `data/fixtures/` to contain the fire, wind and places files with their source URLs.

7. Submission text is ready: `docs/SUBMISSION.md` has no `TODO` left (video link, team names, submission receipt).

8. Human step: submit the form, then save the receipt (time and confirmation) in `docs/SUBMISSION.md`.

## What must be true before we stand up

`docs/TEST-BEFORE-DEMO.md` is the list of things only a human can check (Telegram, the phone, clicking the dashboard). M4 does not replace it.
